# Numbers and precision

## While a formula runs

Calculations use JavaScript numbers (binary doubles) for ordinary numeric values. The `+`, `-` and `*` operators also preserve whole-number arithmetic exactly while the result has at most 400 digits; beyond that limit they return `?`. Decimal arithmetic has special handling, so common decimal operations such as `0.1 + 0.2` produce `0.3`. `+` and `-` of two numbers written with up to 15 decimal places give the result with no more places than the longer of the two when it fits in 15 digits, so `123.45 - 123` is `0.45` and not the `0.4500000000000028` that doubles give; an operand with more places (`1 / 3`) or a result past 15 digits is left to the general handling. `Mod` and `Div` of decimals treat an exact decimal multiple as one (`Mod ( 0.7 ; 0.1 )` is `0`, `Div ( 0.7 ; 0.1 )` is `7`). `Sum` and `Average` keep every digit of a whole number up to 2^53, but a decimal past its 15th significant digit is still rounded (`Sum ( 0.1234567890123456 )` is `0.123456789012346`), and a total of 16 digits or more with decimals is not rounded to the decimal places of its inputs. `SerialIncrement` adds exactly to a digit run of up to 400 digits and returns `?` for an amount that is not a finite whole number the engine holds exactly (`1/0`, `1e30`) and for a longer run; `NumToJText` returns `?` for a non-finite separator or style and, with separator style 2 or 3, for a number of more than 20 digits (the units stop at 京). The store's serial increment is a separate implementation and is not yet changed. `Round`, `Truncate` and `SetPrecision` use decimal-aware calculation paths. `SetPrecision` can format a repeating result to the requested number of decimal places. Functions other than `+`, `-` and `*` may round values past 2^53 today. The current acceptance tests pin correct behaviours, and [whole-numbers.test.ts](../packages/calc/test/whole-numbers.test.ts) covers the existing large-integer cases without making every current loss permanent.

Custom functions that return a recursive call through `If`, `Case` or `Let` use an explicit loop and reach the 10,000-call limit. Non-tail custom recursion still uses the JavaScript call stack: the generated `Sum1 ( n ) = If ( n <= 0 ; 0 ; n + Sum1 ( n - 1 ) )` test succeeds at 500 levels, while 5,000 levels returns `?` on this Node build. The failure point varies with the stack available to the process. Support for deeper non-tail recursion is not implemented; see [the recursion-depth research note](research/recursion-depth.md). ## What is stored

In a synthetic store, writing `9007199254740993` and reading it through `Store.get` returned `9007199254740992`; writing `12345678901234567890` returned `12345678901234567000`. This shows precision was lost by the store's number-field read path. ## What leaves the server

The Data API serializes record field data as JSON. Because the store read path already returned rounded JavaScript numbers, a JSON client receives rounded digits for these inputs; this is an inference from the store probe and serialization path, not an end-to-end HTTP probe. The web client's display path formats JavaScript numbers with `Intl.NumberFormat` and at most two fraction digits; this is an implementation observation, not a rendered-page probe. The SQL wire formats numeric values as text and has a binary numeric encoding, but the exact output for stored `1e21` and a 20-digit field value was not probed end to end.
